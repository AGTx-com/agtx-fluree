# Engine bug records

One record for each engine bug confirmed on the stock Fluree DB v4.2.9 release (`3b8d19e649a6`, the release binary of upstream commit `4b8fa30e`). Each fix lands on `main` as its own commit; bug 9 has two, the fix and a test of its known error case. A fixed bug keeps its record, so the stock measurements and reproductions stay with it.

Keep this folder private: a bug marked "report privately" lets a policy allow what it should refuse, or lets someone read or write what they should not. Nothing here has been reported to Fluree.

Each record states what goes wrong with a minimal example, its measured scope, its cause in the source, what the standards and Fluree's docs say, the fix or proposed fix, a workaround, its history and how to reproduce it. Its folder, of the same name, holds the reproduction scripts and recorded outputs; bug 9 is reproduced with the fork's own engine tests instead. The scripts need Python 3 and take a Fluree binary as their first argument (`python3 -I <script> <fluree-binary>`); they make and remove their own temporary ledgers or servers. The two signing scripts also need the `cryptography` package.

The records name three kinds of build: the stock v4.2.9 release; the fork's full-patch build (the `full-patch` branch's tree before bug 8's fix: fixes 1 to 7 plus this fork's own features; the build most recorded outputs were compared on); and a build of `main` or of a fix branch at a named commit.

## Documented deviations that store wrong data

Not bugs: Fluree's own docs describe this behaviour, so the code does what Fluree promises. Each is recorded here because it silently stores wrong data for standard input; any standard-conforming change makes the same input behave differently from the docs, so the change is a feature on `full-patch`, behind switches.

| Deviation | Effect on stock 4.2.9 | Fluree's docs | JSON-LD 1.1 | Change |
|---|---|---|---|---|
| A URL `@context` is read as a vocabulary prefix and never loaded | A W3C Verifiable Credential 2.0, which must name `https://www.w3.org/ns/credentials/v2` first, is accepted and stored as wrong facts with no warning: `id` and `type` lose their meaning, the credential and its subject become blank nodes, and the claims never reach the subject | `docs/reference/compatibility.md`: "A remote context is not fetched. A string `@context` sets `@vocab` to that string" | A context that can't be dereferenced aborts processing with `loading remote context failed` | Planned feature 15, pinned JSON-LD contexts: [record and reproduction on `full-patch`](https://github.com/AGTx-com/agtx-fluree/blob/full-patch/features/15-pinned-json-ld-contexts.md) |
